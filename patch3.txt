Subject: [PATCH] chore: repo hygiene, env ignore rules, security headers

Three cleanup items, none touching application logic.

1. Untrack build/scratch artifacts: .quasar/ (5 generated files), a stray
   '...swp' vim swap file, and three .scratch-*.mjs throwaway scripts.

2. .gitignore covered .env and .env.test only. Vite actually loads .env.local,
   .env.production and .env.<mode>.local - none of which were ignored. Nothing
   has leaked (scanned for service-role keys, Stripe keys and JWTs: clean), but
   the gap was one 'cp .env.example .env.local' away from being real. Also adds
   .quasar/, /dist/, *.swp and .scratch-* so item 1 stays fixed.

3. vercel.json set no security headers at all. For a site that connects crypto
   wallets, missing frame-ancestors/X-Frame-Options is the standard precondition
   for a drainer overlay. Adds X-Content-Type-Options, X-Frame-Options,
   Referrer-Policy, HSTS and Permissions-Policy as enforced, plus a
   Cache-Control rule for static data payloads.

   CSP ships as Report-Only deliberately. connect-src has to cover Supabase,
   four EVM/Solana RPCs, Algonode and two IPFS pinning services; three.js needs
   'wasm-unsafe-eval'; Quasar emits inline styles. Enforcing that blind would
   break the app on first deploy. Watch the violation reports, tighten, then
   flip the header name to Content-Security-Policy.
